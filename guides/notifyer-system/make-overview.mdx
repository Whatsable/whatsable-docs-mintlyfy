## Module Reference

### Triggers

Instant triggers fire in real time whenever a qualifying event occurs in your Notifyer console. Both triggers below use the **WhatsAble for WhatsApp Business** app in Make and require a webhook plus your Notifyer API key connection.

<Info>
  Both triggers are **Instant** — they fire immediately when a message event occurs in your Notifyer console.
</Info>

---

### Setting up a Notifyer trigger in Make

Both Notifyer triggers follow the same 5-step setup in Make. The only difference is which trigger you select in Step 1.

<Steps>
  <Step title="Step 1 — Select your trigger">
    1. In your scenario, click the large **+** button to add a module
    2. Search for **WhatsAble** or **WhatsAble for WhatsApp Business**
    3. Open the **WhatsAble for WhatsApp Business** app
    4. Under **Triggers**, select the trigger you need:

    | Trigger | When to use it |
    |---------|----------------|
    | **Incoming Messages from console (Notifyer System)** | Fires only when a contact sends your business a message |
    | **Incoming & Outgoing Messages from console (Notifyer System)** | Fires on every message — both incoming and outgoing, including replies typed in the WhatsApp Business app |
  </Step>

  <Step title="Step 2 — Create a webhook">
    After selecting the trigger, the module configuration window opens. The first required field is **Webhook**.

    1. Click the **Add** button next to the **Webhook** dropdown (the dropdown will show "Choose a hook..." if no webhook exists yet)
    2. This opens the **Create a webhook** dialog
  </Step>

  <Step title="Step 3 — Name your webhook and set up a connection">
    In the **Create a webhook** dialog:

    1. Enter a **Webhook name** — use something descriptive so you can identify it later (e.g. `My Notifyer Systems webhook`)
    2. Under **Connection**, either:
       - Select an existing connection if you have already connected Notifyer to Make before, **or**
       - Click **Add** next to the Connection dropdown to create a new connection (continue to Step 4)
    3. If you already have a connection selected, click **Save** to create the webhook and skip to Step 5
  </Step>

  <Step title="Step 4 — Create your Notifyer connection (first time only)">
    If you clicked **Add** in Step 3, the **Create a connection** dialog opens on top of the webhook dialog.

    1. Enter a **Connection name** (e.g. `My Notifyer only connection`)
    2. Paste your **Notifyer API key** in the **API Key** field — get this from your [Notifyer API Keys page](https://console.notifyer-systems.com/api-key)
    3. Click **Save**

    Make validates your API key automatically. Once saved, you return to the **Create a webhook** dialog with your new connection selected.

    <Info>
      You only need to create this connection once. All future Notifyer modules in Make can reuse the same saved connection.
    </Info>

    Back in the **Create a webhook** dialog, click **Save** to finish creating the webhook.
  </Step>

  <Step title="Step 5 — Save the trigger and activate your scenario">
    You are now back in the main module configuration window. The webhook you created is selected and a **Webhook URL** is displayed (e.g. `https://hook.eu1.make.com/...`).

    1. Confirm your webhook is selected in the **Webhook** dropdown
    2. Click **Save** to finish configuring the trigger module
    3. Toggle your scenario to **Active** (or click **Run once** to test first)

    <Check>
      Your trigger is now live. When a matching message event occurs in your Notifyer console, Make will run your scenario automatically.
    </Check>

    <Tip>
      Set the scenario schedule to **Immediately as data arrives** (shown in the bottom toolbar) so instant triggers fire without delay.
    </Tip>
  </Step>
</Steps>

#### Incoming Messages from console (Notifyer System)

<Info>
  **Type:** Instant Trigger | **Connection:** Notifyer only
</Info>

Fires every time an **incoming message** arrives in your Notifyer console. This is the full-featured trigger for building AI chatbot workflows, lead qualification, CRM updates, and real-time automations — it exposes all conversation context fields including the AI note, conversation history, and scheduling data.

**Description in Make:** *"Incoming Messages from console (Notifyer System)"*

**How to set up:** Follow the [5-step trigger setup guide](#setting-up-a-notifyer-trigger-in-make) above. In Step 1, select **Incoming Messages from console (Notifyer System)** from the Triggers list.

**Output fields — everything your scenario receives when triggered:**

<AccordionGroup>
  <Accordion title="Contact identity">
    <ResponseField name="phone_number" type="text">
      The phone number of the person who sent the message (e.g. `14155550187`)
    </ResponseField>
    <ResponseField name="user_id" type="text">
      Unique internal ID for this contact in Notifyer (UUID format)
    </ResponseField>
    <ResponseField name="recipient_name" type="text">
      The first name or display name used by the AI to address this contact in conversation
    </ResponseField>
    <ResponseField name="labels" type="text">
      Comma-separated list of labels currently applied to this conversation (e.g. `Hot Lead, Buyer Qualified, Urgent`)
    </ResponseField>
  </Accordion>
  <Accordion title="Message data">
    <ResponseField name="message_type" type="text">
      Type of the incoming message: `text`, `audio`, `image`, or `document`
    </ResponseField>
    <ResponseField name="incoming_message" type="boolean">
      `true` for this trigger — confirms this is an inbound message from the contact
    </ResponseField>
    <ResponseField name="send_by" type="text">
      Empty on this incoming-only trigger. On the incoming **and outgoing** trigger, this identifies the sending system or teammate (see below)
    </ResponseField>
    <ResponseField name="was_message_by_human" type="boolean">
      `true` when a person sent the message
    </ResponseField>
    <ResponseField name="attachment_url" type="text">
      Public URL of any file the contact attached (image, document, audio). Empty if no attachment
    </ResponseField>
    <ResponseField name="is_scheduled" type="boolean">
      `true` if triggered by a scheduled message being delivered; `false` for real-time messages
    </ResponseField>
  </Accordion>
  <Accordion title="Conversation history">
    <ResponseField name="last_messages" type="text">
      JSON array of recent messages. Each item includes: `type` (user/bot), `content`, `timestamp`, `content_type`. Useful for passing full history to an AI
    </ResponseField>
    <ResponseField name="last_message_of_user" type="text">
      The most recent message sent by the contact — the message that triggered this run
    </ResponseField>
    <ResponseField name="last_message_of_bot" type="text">
      The most recent message your business sent to this contact — helps AI avoid repeating itself
    </ResponseField>
    <ResponseField name="user_last_message_time" type="number">
      Unix timestamp (ms) of when the contact's last message was received
    </ResponseField>
    <ResponseField name="bot_last_message_time" type="number">
      Unix timestamp (ms) of when your business last messaged this contact
    </ResponseField>
    <ResponseField name="conversation_paragraph" type="text">
      A flat, readable version of the full conversation history — ideal for passing directly to an AI/LLM prompt without parsing the `last_messages` JSON array
    </ResponseField>
  </Accordion>
  <Accordion title="AI context & automation fields">
    <ResponseField name="note" type="text">
      The AI context note stored on this contact in Notifyer. Contains lead details: name, email, preferences, background, language, etc. Set this via the **Update a Contact** action or directly in the Notifyer console
    </ResponseField>
    <ResponseField name="note_automation" type="text">
      Automation instructions for the AI — rules the AI follows automatically based on conversation events (e.g. "If budget confirmed and timeline under 6 months, notify the agent within 1 hour")
    </ResponseField>
    <ResponseField name="scheduled_messages" type="text">
      Description of any messages currently queued/scheduled to be sent to this contact at a future time
    </ResponseField>
  </Accordion>
</AccordionGroup>

#### Incoming & Outgoing Messages from console (Notifyer System)

<Info>
  **Type:** Instant Trigger | **Connection:** Notifyer only
</Info>

Fires on **both incoming and outgoing** messages — every message sent or received in your Notifyer console triggers this, including messages **typed by hand in the WhatsApp Business app**. Use it for conversation logging, CRM sync, or automations that must react when a teammate replies on their phone.

**Description in Make:** *"Get your sent and incoming messages data through a single webhook."*

**How to set up:** Follow the same [5-step trigger setup guide](#setting-up-a-notifyer-trigger-in-make) above. In Step 1, select **Incoming & Outgoing Messages from console (Notifyer System)** instead.

**Key difference:** This trigger also fires when your business sends a message. Use the `incoming_message` field to branch your logic:
- `incoming_message = true` → a contact sent your business a message
- `incoming_message = false` → your business sent a message to a contact (phone app, Notifyer inbox, or automation)

**Output fields:** Identical to the **Incoming Messages from console** trigger above, with these differences:

<ResponseField name="incoming_message" type="boolean">
  `true` when the contact sent a message, `false` when your business sent a message. Add a **Router** or **Filter** module after this trigger to branch logic based on direction
</ResponseField>

<ResponseField name="send_by" type="text">
  Which system or person sent an outgoing message: `"WhatsApp App"` for the WhatsApp Business app, the teammate's name for the Notifyer chat inbox, or the automation/app name for Make, Zapier, n8n, or API
</ResponseField>

<ResponseField name="was_message_by_human" type="boolean">
  `true` when a person sent the message (phone app or Notifyer inbox). `false` when a bot or automation sent it
</ResponseField>

<Note>
  The `scheduled_messages` field is only available in the **Incoming Messages from console** trigger, not this one.
</Note>

#### Send WhatsApp Message

<Info>
  **Type:** Action | **Connection:** Notifyer only
</Info>

Labels and notes set here appear directly in your Notifyer console — making this the primary send module for Notifyer System users.

**API endpoint:** `https://api.insightssystem.com/api:pqxobaAo/send`

#### Schedule a follow-up Message

<Info>
  **Type:** Action | **Connection:** Notifyer only
</Info>

**Description in Make:** *"Schedule a follow-up to get sent later and add conditions so it only gets sent if the lead did not reply to you."*

Schedule a WhatsApp message to be sent at a **future time**, with an optional **reply condition** that automatically cancels the message if the recipient responds before it sends. This is one of Notifyer's most powerful automation features — use it to build no-reply follow-up sequences, re-engagement drips, and smart nurture workflows.

**How to configure:**

<Steps>
  <Step title="Add the module">
    Click **+** → search for **WhatsAble** or **WhatsAble for WhatsApp Business** → under **Actions**, select **Schedule a follow-up Message**
  </Step>
  <Step title="Select your connection">
    Choose your **Notifyer only** connection
  </Step>
  <Step title="Choose your message type">
    Select from the **Configuration** dropdown — either a template message or a non-template message. The fields are identical to the **Send WhatsApp Message** action above (phone number, template/message type, variables, labels, note).
  </Step>
  <Step title="Set when to send it">
    <Tabs>
      <Tab title="Relative (Delay)">
        Send the message after a delay from the time the scenario runs:

        <ResponseField name="Delay Value" type="select" required>
          Choose: 1, 2, 3, 4, 5, 10, 15, 20, 30, 60, 90, or 120
        </ResponseField>
        <ResponseField name="Delay Unit" type="select" required>
          Choose: **Minutes**, **Hours**, or **Days**
        </ResponseField>
      </Tab>
      <Tab title="Specific Date & Time">
        Send the message at an exact date and time:

        <ResponseField name="Date & Time" type="datetime" required>
          The exact date and time to send the message
        </ResponseField>
        <ResponseField name="Timezone" type="select" required>
          The timezone for the scheduled time — full global timezone list available (GMT-11 through GMT+12)
        </ResponseField>
      </Tab>
    </Tabs>
  </Step>
  <Step title="Set a reply condition (recommended)">
    The reply condition tells Notifyer to **cancel the scheduled message** if the recipient replies within the specified timeframe — preventing follow-ups to contacts who are already engaged.

    <ResponseField name="Reply Condition" type="select">
      | Condition | When the message is cancelled |
      |-----------|-------------------------------|
      | Recipient did not reply after my last message | Cancelled if the contact replies at any point before scheduled send |
      | Recipient never replied to any of my messages | Cancelled only if the contact has never replied to you at all |
      | Recipient did not reply within 20 minutes | Cancelled if contact replies within 20 minutes |
      | Recipient did not reply within 45 minutes | Cancelled if contact replies within 45 minutes |
      | Recipient did not reply within 3 hours | Cancelled if contact replies within 3 hours |
      | Recipient did not reply within 6 hours | Cancelled if contact replies within 6 hours |
      | Recipient did not reply within 12 hours | Cancelled if contact replies within 12 hours |
      | Recipient did not reply within 24 hours | Cancelled if contact replies within 24 hours |
      | Recipient did not reply within 48 hours | Cancelled if contact replies within 48 hours |
      | Recipient did not reply within 72 hours | Cancelled if contact replies within 72 hours |
    </ResponseField>

    <Tip>
      **"Recipient did not reply after my last message"** is the recommended default for most follow-up sequences — it ensures no follow-up is sent to contacts who are already in conversation with you.
    </Tip>
  </Step>
  <Step title="Set a label condition (optional)">
    Restrict the scheduled message to only send if the contact has (or does not have) a specific label:

    <ResponseField name="Label Condition" type="select" optional>
      **Include** — only send if the contact has this label  
      **Does Not Include** — only send if the contact does NOT have this label
    </ResponseField>
    <ResponseField name="Label" type="select" optional>
      The label to evaluate against
    </ResponseField>
  </Step>
</Steps>

<Note>
  Scheduled messages are visible in your Notifyer console under the contact's conversation. You can view or cancel them there at any time.
</Note>

#### Update a Contact

<Info>
  **Type:** Action | **Connection:** Notifyer only
</Info>

**Description in Make:** *"Assign conversation to someone in your team, Add information in the notes, add/remove labels. Simply put the phone number and what information you want to change. This appears in the chat interface of our system."*

Update a contact's details in your Notifyer console — set their display name, add or remove labels, or update the AI context note on their conversation. Use this to keep Notifyer contacts in sync with your CRM, form responses, or other external data.

**API endpoint:** `https://api.insightssystem.com/api:hFrjh8a1/make/recipient/details/update` (PUT)

**How to configure:**

<Steps>
  <Step title="Add the module">
    Click **+** → search for **WhatsAble** or **WhatsAble for WhatsApp Business** → under **Actions**, select **Update a Contact**
  </Step>
  <Step title="Select your connection">
    Choose your **Notifyer only** connection
  </Step>
  <Step title="Fill in the fields">
    <ResponseField name="Phone Number" type="text" required>
      The phone number of the contact to update, in international format — digits only (e.g. `14155550187`). This is used to look up the contact in Notifyer
    </ResponseField>
    <ResponseField name="Display Name" type="text" optional>
      Update the display name shown for this contact in the Notifyer chat interface
    </ResponseField>
    <ResponseField name="Add a Note" type="text" optional>
      Set or update the AI context note for this contact. The AI reads this field to personalize conversations. A well-structured note significantly improves AI response quality.

      **Recommended note format:**
      ```
      email: john@example.com | Name: John Smith
      Looking for: 3BR house, $500k budget, north suburbs
      Pre-approved: Yes | Language: English
      Best time to contact: evenings after 6pm
      ```
    </ResponseField>
    <ResponseField name="Add Label Names or IDs" type="multiselect" optional>
      One or more labels to **add** to this contact. Labels appear in the Notifyer console and can be used for routing, filtering, and automation conditions
    </ResponseField>
    <ResponseField name="Remove Label Names or IDs" type="multiselect" optional>
      One or more labels to **remove** from this contact. Select **Remove All** to clear all labels from this contact at once
    </ResponseField>
  </Step>
</Steps>

<Tip>
  Place **Update a Contact** at the very start of your scenario — before sending any message — to populate the AI Note from form or CRM data. This ensures the AI has full context before the first message is even sent.
</Tip>

#### Get delivery status of a message

<Info>
  **Type:** Search | **Connection:** Notifyer only
</Info>

**Description in Make:** *"Check if the message was delivered or not. Use this if you're not sure the number is correct and want to check if it was delivered and want to send a fallback email."*

Check whether a previously sent WhatsApp message was delivered. Use this to build fallback automation — if a message was not delivered (e.g. incorrect number), automatically trigger an alternative action such as sending a fallback email.

**API endpoint:** `https://api.insightssystem.com/api:5l-RgW1B/conversation/{{messageId}}` (GET)

**How to configure:**

<Steps>
  <Step title="Add the module">
    Click **+** → search for **WhatsAble** or **WhatsAble for WhatsApp Business** → under **Searches**, select **Get delivery status of a message**
  </Step>
  <Step title="Select your connection">
    Choose your **Notifyer only** connection
  </Step>
  <Step title="Enter the Message ID">
    <ResponseField name="Message ID" type="text" required>
      The ID of the message to check. This is the ID returned in the output bundle of a previous **Send WhatsApp Message** or **Schedule a follow-up Message** action in the same scenario
    </ResponseField>
  </Step>
</Steps>

<Tip>
  Connect a **Router** module after this search to handle two paths: one for successfully delivered messages, and one for undelivered messages where you trigger a fallback (e.g. send a Gmail or Outlook email).

## Building a complete scenario: step-by-step example

Here is a practical end-to-end example: **New lead from a form → AI context set → Template message sent → Conditional follow-up scheduled**

<Steps>
  <Step title="Trigger: New form submission">
    Start with a **Google Forms**, **Typeform**, or **Jotform** instant trigger that fires when someone fills in your lead capture form
  </Step>
  <Step title="Action: Update a Contact">
    Add **Notifyer — Update a Contact**. Map form fields into the Note field:
    ```
    email: {{email}} | Name: {{name}} | Budget: {{budget}} | Language: {{language}}
    ```
    Add relevant labels: `New Lead`, `Form Submission`

    This gives the AI complete context before any conversation starts
  </Step>
  <Step title="Action: Send WhatsApp Message (Template)">
    Add **Notifyer — Send WhatsApp Message** set to the template configuration. Select your approved welcome template and map the recipient's phone number and any template variables from the form data
  </Step>
  <Step title="Action: Schedule a follow-up Message">
    Add **Notifyer — Schedule a follow-up Message**. Configure:
    - Message: a follow-up template (e.g. `Hi {{1}}, just checking in...`)
    - Schedule: 24 hours (Relative)
    - Reply condition: **Recipient did not reply after my last message**

    This follow-up cancels automatically if the lead responds to your first message
  </Step>
  <Step title="Test and activate">
    1. Click **Run once** to test with real data
    2. Verify each module shows a green checkmark
    3. Toggle the scenario **Active** switch to go live
  </Step>
</Steps>

## Best practices

<AccordionGroup>
  <Accordion title="Set the AI Note before sending" icon="robot">
    Always use **Update a Contact** before **Send WhatsApp Message** in new-lead scenarios. Setting the `note` field with structured lead data (name, email, preferences, language, budget) dramatically improves AI conversation quality and lead qualification accuracy.
  </Accordion>
  <Accordion title="Always use reply conditions on follow-ups" icon="shield-check">
    Set a reply condition on every **Schedule a follow-up Message**. "Recipient did not reply after my last message" is the safest choice — it ensures no follow-up annoys contacts who are already in an active conversation with you. This also protects your WhatsApp account reputation.
  </Accordion>
  <Accordion title="Use labels and notes on every send" icon="paper-plane">
    The **Send WhatsApp Message** action lets you attach labels and a note alongside every message. Use labels to tag conversations (e.g. `Hot Lead`, `Form Submission`) and the note field to keep AI context current. Both appear immediately in your Notifyer console.
  </Accordion>
  <Accordion title="Use conversation_paragraph for AI prompts" icon="paragraph">
    When building AI chatbot scenarios, pass the `conversation_paragraph` field to your AI model. It is a pre-formatted, flat text version of the conversation — much simpler to include in a prompt than parsing the `last_messages` JSON array.
  </Accordion>
  <Accordion title="Use Incoming & Outgoing trigger for full logging" icon="list">
    If you need to log every message exchange to a CRM or database, use **Incoming & Outgoing Messages from console** and filter by `incoming_message` to handle both directions with separate scenario branches.
  </Accordion>
  <Accordion title="Phone number format" icon="phone">
    Always provide phone numbers in full international format — digits only, no `+`, spaces, or dashes (e.g. `14155550187` for US, `447911123456` for UK, `966501234567` for Saudi Arabia).
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Trigger not firing?" icon="circle-exclamation">
    <Steps>
      <Step title="Check the scenario is active">
        Instant triggers only fire when the scenario is toggled **Active** in Make. Also confirm the schedule is set to **Immediately as data arrives**
      </Step>
      <Step title="Verify the webhook is configured">
        Open the trigger module and confirm a webhook is selected in the **Webhook** dropdown and a **Webhook URL** is displayed. If the field is empty, follow the [trigger setup guide](#setting-up-a-notifyer-trigger-in-make) to create one
      </Step>
      <Step title="Verify your connection">
        Open the connection settings and confirm your Notifyer API key is valid and the connection shows a green tick
      </Step>
      <Step title="Re-register the webhook">
        Try deactivating and reactivating the scenario — this re-registers the webhook with Notifyer. Check your Notifyer console to confirm messages are arriving there
      </Step>
      <Step title="Check Notifyer console">
        If messages appear in your Notifyer console but the trigger does not fire, contact support
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Messages not sending?" icon="message-xmark">
    <Steps>
      <Step title="Check the connection">
        Verify your Notifyer API key is valid and the correct connection is selected
      </Step>
      <Step title="Check phone number format">
        Phone number must be digits only, full international format, no `+` or spaces (e.g. `14155550187`)
      </Step>
      <Step title="Template not approved?">
        Ensure the selected template has **Approved** status in your Notifyer dashboard. Pending or rejected templates will cause an error
      </Step>
      <Step title="24-hour window for non-template">
        Non-template messages can only be sent within 24 hours of the contact's last incoming message. Outside this window you must use a template
      </Step>
      <Step title="Check subscription credits">
        Verify your Notifyer subscription is active and has sufficient message credits
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Template variables not populating?" icon="brackets-curly">
    <Steps>
      <Step title="Fill all required variable fields">
        All body variable fields (Body 1, Body 2, etc.) are required — ensure none are empty or mapped to empty values
      </Step>
      <Step title="Check the template preview">
        The template dropdown shows a live preview of the body text and example variable values — use this as a reference to understand what each variable slot expects
      </Step>
      <Step title="Media URL must be public">
        If your template has a media header, the URL must be publicly accessible. Test it in an incognito browser window
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Scheduled message was not sent?" icon="clock">
    <Steps>
      <Step title="Reply condition may have cancelled it">
        If you set a reply condition and the contact replied before the scheduled time, the message was intentionally cancelled. Check the contact's conversation in your Notifyer console
      </Step>
      <Step title="Check the scheduled time">
        Verify the delay value and unit are correct (minutes vs hours vs days)
      </Step>
      <Step title="Check scenario run history">
        Go to Make scenario history to confirm the Schedule a follow-up module executed without errors at the time the trigger fired
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Update a Contact changes not appearing in Notifyer?" icon="user-pen">
    <Steps>
      <Step title="Verify the phone number">
        The phone number must exactly match the contact's number in Notifyer. If the contact doesn't exist yet, the update creates the record
      </Step>
      <Step title="Check you're using the right connection">
        Update a Contact requires the **Notifyer only** connection — make sure you are not using a different connection type
      </Step>
    </Steps>
  </Accordion>
</AccordionGroup>
